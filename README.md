## 启动与使用

源码启动需要 Windows、64 位 Python 3.11 和 WebView2 Runtime；便携版附带 Python。普通服务使用标准库；地图转换额外使用 NumPy、Pillow 和随包的 imagecodecs，便携版已附带。游戏为 x86；随项目提供的 Hook 也为 x86。

双击 `Start Camera Lab.cmd`，或在项目目录执行：

```powershell
python -X utf8 -B -m blitzcam desktop
```

更新后需重新启动 Python 服务。页面版本应为 `0.7.2 · STEAM 11.21`。服务只监听 `127.0.0.1`，默认离线；`--no-browser` 可禁止自动打开网页。关闭终端或按 Ctrl+C 退出服务，退出时会请求撤下镜头 Hook。

1. 在 Blitz Camera 顶部点击“选择回放文件…”，模式二会自动加载离线预览。需要实机拍摄时，点击旁边的“在游戏中播放项目回放”，等候游戏载入，切到自由镜头并暂停，松开按键和滚轮。
2. 点击“连接客户端”，等待左侧显示暂停时间和镜头状态。
3. 点击“从当前机位新建轨迹”，将当前镜头保存到实际对局时刻。旧项目自动备份到 `output/project-history`。
4. 在游戏内调到下一对局时刻，暂停，移到下一机位并停稳，点击“捕获当前机位”。时间自动读取当前暂停的回放时钟。
5. 用 XYZ、摄像机水平角度、俯仰、横滚、缩放和时间编辑路径。可选择直线分段或平滑曲线，并先在下方离线预演中检查形状。位置、朝向与缩放已有基础组合轨迹实测。
6. 在主时间轴设置入点和出点，点击主播放按钮：工作区内从当前暂停时刻继续至出点，入点之前先准备入点再开拍。已越过入点时，可用橙色播放栏的实验性跳转按钮，或退出并重新打开回放。机位的绝对时间不会随区间变化而重排；单次游戏内播放区间最长 120 秒。
7. 点击“停止”，或在工作台页面按 Esc，中途停止并保留当前构图；结束或停止后交还手动控制。

正向按第一个到最后一个机位执行，反向按同一条已编排轨迹倒序执行。若当前镜头不在起点，先用约 1–3 秒移动到所选端点，再开始计算设定的整段时长；这段准备移动采用抬高的平滑路线，界面会显示“正在移到轨迹端点”。准备移动也可停止。

**开始前请暂停回放，播放期间不操作游戏镜头。** 0.4.0 可选择战斗保持暂停、固定倍率或速度曲线。 检测到非预期的暂停状态、倍率、跳转、输入、缩放、朝向、对象关联或原生位置校正变化时，会停止接管并报告原因。执行前检查自由镜头边界及已识别的限制体积；这不等于完整的地图碰撞检测，平滑曲线仍可能穿过场景。

## 轨迹时间与镜头通道

- 游戏内轨迹支持 0.5–120 秒、2–200 个机位。默认战斗保持暂停。新增固定 1×、1/2×、1/4×、1/8×、1/16× 及自定义速度曲线，允许倍率范围 1/16×–1×。
- 速度曲线有 2–64 个关键帧，按整段拍摄进度 0%–100% 编排，支持线性/平滑过渡，随项目保存和导入导出。倍率积分与镜头路径弧长/缓动分别处理。
- “按拍摄时间运动”：整段时长是实际拍摄时间，战斗慢放不会拖慢镜头；“跟随回放时间运动”：整段时长是战斗推进时间，慢放时实际拍摄更长。当前源码已分开处理两种时长：回放区间仍最多 120 秒，慢放后的实际拍摄最多 1920 秒（120 秒 ÷ 最低 1/16×），不会增加轨迹采样点；退出监控按实际拍摄长度计算。工作区超过速度曲线范围时保持端点倍率，速度页会明确显示对应倍率和换算时长。
- “固定当前镜头，仅播放回放”可单独检查速度，不改变已保存的机位轨迹；其时长始终指拍摄时间。
- “暂停联动”同时暂停镜头和战斗，“继续联动”从当前位置继续；停止/完成恢复原倍率并保持战斗暂停，保留当前构图。就位阶段保持战斗暂停，反向只倒序运动镜头，战斗仍正向推进。
- “遵守关键帧时间”保留各机位的到达时刻，段间速度可以不同。
- “按整条路径弧长分配”按距离重新分配内部机位的到达时间。配合“匀速进度”可得到近似空间匀速；内部机位原时间不再生效。
- 缓入、缓出和缓入缓出控制时间到路程的映射。反向播放是同一映射的时间反转。
- Hook 在游戏原生更新之后提交镜头状态，并在阴影绘制入口只读记录。它不反复调用此前会导致阴影刷新的目标提交入口，也不改写阴影数据。动态缩放下的阴影效果仍待实机核对。
- 朝向和缩放默认沿关键帧变化；朝向用四元数最短旋转插值。旧项目若所有机位角度和缩放相同，不会产生转向或变焦。
- 轨迹俯仰范围为 ±80°；缩放依据当前视口换算到内部 5–90° 区间。工具使用相机基底横滚，原生控制器额外横滚仍须为零；缩放动画未空闲时不接管。

离线编辑仍支持四元数姿态、缩放、三维/XY/XZ/YZ 预演和 JSON 导入导出，项目上限为 200 帧、1 小时。离线预演没有游戏地图和实际画面，不提供碰撞校正。世界单位尚未独立标定为米；界面角度由视图矩阵换算，缩放沿用水平角度值，与游戏内部接口数值不同。项目文件和内部协议的字段名保留，以兼容已有机位。

## 文件与诊断

- 当前源码会将连接失败、连接成功、项目切换，以及关联/播放请求被拒绝时的错误与时间区间写入 `output/diagnostics/events.jsonl`。每个文件最多约 1 MiB，保留 3 份轮转备份；只在操作或状态变化时记录，不持续扫描游戏。旧安装包不具备这些新增记录，需随程序更新生效。
- 笔记本偶发问题可单独复制 `Collect Support Logs.cmd` 到 `BlitzCamera.exe` 旁边。报错后保持软件打开并双击，生成 `output/support-logs/BlitzCamera-logs-*.zip`。不需要重装或安装 Python；输出目录不可写时保存到临时目录，并显示完整路径。工具只读取当前服务状态和已有日志，不重新连接或扫描游戏。包内含连接错误、游戏回放时刻、保存的区间和倍率、系统内存快照，以及最近三次已有的播放/连接诊断记录；不含项目原文件、回放内容、授权密钥或浏览器缓存，不自动上传。软件已关闭时仍能收集历史日志，但无法恢复未落盘的报错现场。
- 新项目默认保存在系统“文档/Blitz-Camera-Project”；普通启动显示主页，也可用 `serve --project output/my-shot.json` 显式打开指定项目。
- 原始暂停机位：`output/captures`。
- 新建轨迹时的旧项目：`output/project-history`。
- 每次游戏内执行：`output/playback-runs/<UTC>/report.json`、`events.jsonl` 和 `operations.jsonl`，包括配置、更新/绘制样本、终点状态和撤下结果。
- 连接提示“未确认唯一的回放自由镜头对象链”或“启动参数没有唯一回放文件”时，可把独立的 `Collect Camera Diagnostics.cmd` 放在便携版 `BlitzCamera.exe` 旁边，保持报错时的回放状态并双击。脚本使用该版本自带的读取模块，保存候选数量、关联校验失败细节及读取错误到 `output/connection-diagnostics/*.json`。第 2 版对精确适配的 11.21 构建额外记录场景实际相机、回放暂停状态及游戏更新链指向的控制器类型，缺少预期控制器时也会收集这些信息。第 3 版还单独记录启动参数中的回放路径及其数量，区分没有文件、重复同一文件、多个不同文件和参数读取失败，不记录其他选项内容；这些额外观察不代替连接或文件校验。第 4 版修复交付文件的换行格式导致命令行闪退的问题，固定使用 Windows CRLF；启动时先保存 `output/connection-diagnostics/diagnostic-startup.log`，即使目录错误、运行环境缺失或 Python 启动失败，窗口也会等待按键。输出目录不可用时改存 `%TEMP%/BlitzCamera-diagnostic-startup.log`，窗口会显示完整位置。测试直接保留交付字节，覆盖中文、空格及特殊字符目录，避免测试复制时自动修正换行。只读取游戏，不加载 Hook、不切换回放，也不修改项目；脚本可单独传给另一台电脑，无需重新打包程序。
- `examples` 中的项目是历史离线示例，部分数值人为安排，不能直接当作当前地图上的安全路线。

## 离线升级发布（0.9.6 beta）

下面是维护者流程，不出现在用户界面。客户端只呈现“升级包”“导出配置”，两类更新统一使用 `.bcupdate`。不提供联网更新检查、账号或授权服务器。

### 发布身份与备份

首次建立发布身份（当前工作区已执行，勿重新生成）：

```powershell
python tools/publish_updates.py --key output/publisher/publisher.dpapi init
```

公钥位于 `blitzcam/package-trust.json`，随主程序分发；私钥位于 `output/publisher/publisher.dpapi`，通过 Windows 当前用户 DPAPI 保护，禁止分发。发布工具只在维护者电脑运行，不进入客户包。不要随意更换公钥，否则已有安装无法接受新签名。

务必另做可迁移备份；单独复制 DPAPI 文件不能保证在新电脑或重装 Windows 后恢复。下列命令交互输入至少 16 字符的强口令，不把口令放进命令行或文件：

```powershell
python tools/publish_updates.py --key output/publisher/publisher.dpapi backup-key --output output/publisher/publisher-backup.bcsecret
# 换机时复制公钥文件和加密备份，使用相同口令恢复到不存在的新私钥文件。
python tools/publish_updates.py --key output/publisher/restored.dpapi restore-key --backup output/publisher/publisher-backup.bcsecret
```

将加密备份放入独立备份介质，口令另存。备份使用 PBKDF2-HMAC-SHA256（600000 次）和 AES-256-GCM；日常发布继续使用本机 DPAPI 私钥。

### 主程序更新

首次将 0.9.6 beta 完整包解压到用户可写目录。旧版没有升级入口，需要这一次完整基线。保留每次发布的原始解压目录及 `manifest.json`，以后构建新版本并制作文件级增量：

```powershell
python tools/build_overlay.py
python tools/package_desktop.py --destination dist/BlitzCamera-新版本
python tools/publish_updates.py --key output/publisher/publisher.dpapi app --base dist/BlitzCamera-旧版本 --target dist/BlitzCamera-新版本 --output dist/BlitzCamera-旧版本-to-新版本.bcupdate --notes "本次更新说明"
```

包只携带新增或变化文件及完整目标清单，使用 RSA-3072-PSS/SHA-256 签名。界面先验签、检查基线及本地文件，再保存编辑器、退出应用，由外部进程切换目录并自动重开。未变化的大体积依赖不重复分发。运行环境或启动器变更需要新的完整基线，发布工具会明确拒绝生成不兼容的增量包。各旧基线分别生成对应升级包，也可从更早的兼容基线直接生成跨版本包。

升级保留 `output`、默认项目目录与已部署的适配包；新版移除的程序文件不会残留。切换前备份到 `output/deployment/backups`，逐步记录事务。失败自动回退；断电或进程异常后，再次启动会先恢复。暂存与备份需要额外磁盘空间；确认新版稳定后可人工归档旧备份，勿删除进行中的事务和 helper。

### 设备专属适配包

1. 用户在实际使用的安装目录中打开“设置 → 升级包 → 导出配置”，交付 `.bcconfig`。该文件只有版本、设备公钥及保护类型，不包含私钥、项目或游戏数据。
2. 发布者为该公钥单独生成加密包；每次包使用新的 256 位随机 AES 密钥、96 位随机 nonce 和 128 位 GCM 标签，RSA-OAEP/SHA-256 封装给设备公钥，外层再签名。
3. 用户从同一页面选择并部署。成功后立即显示紫红色 Pro，并开放相关操作；已加载游戏组件的进程须先退出重开，再导入下一适配包，避免运行中混用组件。

```powershell
python tools/publish_updates.py --key output/publisher/publisher.dpapi pro --config 用户导出的.bcconfig --version 11.21-r1 --game-sha256 5030ee4b9f6ec7db1c06efa2b92f9dd7243574be5d8d9578c118119318bc9608 --output dist/给该用户的升级包.bcupdate --notes "适配更新"
```

同一个配置可持续生成后续更新，无须每次重新导出。设备密钥优先使用 TPM；不可用时使用 Windows 当前用户的不可导出软件密钥。复制加密包和应用目录到另一台电脑或另一个 Windows 用户不能直接解密。0.9.6-beta.1 起，关闭程序、等待发包、改用另一个安装目录都不需要重新导出；登记文件丢失时会按已签名包的设备指纹找回本应用原有的 Windows 密钥。只有原 Windows 私钥确实不可用（例如重装系统或换 Windows 用户）才需重新登记和发包；完全离线不支持远程撤销已发出的包。

适配包包含 `packages.ADAPTER_MODULES` 所列游戏实现、构建布局和原生组件。WoTB 更新后仍需研究与验证新版布局，再通过 `--source` 指定更新后的模块目录；原生清单名称变化时重复传入 `--native-manifest 名称.json`。接口 `adapter_api=1` 不变时无需升级主程序；更改宿主接口则同步发主程序更新。游戏运行仍核对客户端精确 SHA-256，不能只改版本字符串宣称兼容。

保护范围：公开包不含 Hook Python 实现和原生 DLL；加密包可以防普通转发与直接解包读取。授权后 Python 模块在内存编译，Windows 原生 DLL 使用时需写入 `output/deployment/runtime`。接收者控制自己的电脑，仍可能从运行时提取内容或修改客户端；本方案不承诺绝对防逆向，也不提供硬件证明来验证用户提交的公钥确实来自 TPM。

## Pro Studio 与适配母包规范

Pro Studio 是维护者单独使用的离线制作工具，源码位于 `publisher/`，不进入普通客户端。当前成品为 `dist/BlitzCameraProStudio-1.0.0/ProStudio.exe`，压缩包为 `dist/packages/ProStudio-1.0.0/BlitzCameraProStudio-1.0.0.zip`，约 9 MB。自带 Python 3.11，使用本机 WebView2；原生窗口通过标准输入输出调用制作逻辑，不开网络服务。客户端继续只显示“升级包”“导出配置”，此工具不改变其隐藏入口和 Pro 标识规则。

### 日常使用

1. 新版游戏发布后，先完成解析、适配与验证，交付 `adapter.json`、验证记录和 `.bcpro` **内部母包**。这一阶段不需要用户配置或签名私钥。
2. 打开 Pro Studio，在“批量发包”中导入母包；母包自动存入版本库，后续不依赖原源码目录。
3. 导入用户从客户端导出的 `.bcconfig`，可多选。建议先用用户名命名配置文件，方便对照；同一设备自动去重，配置库可供后续各版本重复使用。
4. 勾选用户，点击“生成加密升级包”。每位用户获得独立 `.bcupdate`，把对应文件分别交给本人。
5. 每批输出有 `batch.json` 和 `分发清单.csv`，记录母包版本、设备标识、文件名、包哈希和发布身份。在“发布记录”可查看并打开对应文件夹，最近 100 批显示在界面，完整记录保存在数据目录和各批输出中。

“制作母包”页可以从规范的源码清单生成新母包。“发布设置”可选择发布私钥、公钥文件和输出目录，以及导出带口令的密钥备份、从备份恢复。本机默认沿用 `output/publisher/publisher.dpapi` 和现有客户端信任身份，不会重新生成密钥。移动工具后如路径变化，在设置中重新选择；换 Windows 用户或电脑时，需用加密备份恢复私钥，不能只复制 DPAPI 文件。

工具目录下的 `data/` 保存母包库、公开设备配置、设置、发布记录和界面缓存；升级制作工具时保留该目录。发布私钥单独存放，不复制进工具 ZIP。母包、配置库和发布记录也不会打进工具 ZIP。

当前示范母包为 `output/pro-masters/steam-international-11.21-r1.bcpro`，对应 Steam 国际版 `11.21.0.1235`、精确客户端 SHA-256 `5030ee4b9f6ec7db1c06efa2b92f9dd7243574be5d8d9578c118119318bc9608`。它标准化封装已有适配实现；验证级别为 `offline`，本次未连接游戏或重新执行游戏内实测。

### 三层格式与版本规则

| 文件 | 用途 | 交付对象 |
| --- | --- | --- |
| `adapter.json` + 源码 + 验证记录 | 未来解析和制作的输入，`pro-source-v1` | 内部开发与维护 |
| `.bcpro` | 固定版本的完整适配快照，`pro-master-v1` | 只交给维护者 |
| `.bcupdate` | 按设备加密、由发布者签名的升级包，沿用客户端 v1 协议 | 对应最终用户 |

源码清单规范见 `publisher/schema/pro-source-v1.schema.json`，母包规范见 `publisher/schema/pro-master-v1.schema.json`，宿主接口见 `publisher/schema/adapter-api-v1.json`。当前示例在 `adapters/steam-international-11.21/`，该目录上级的 `AGENTS.md` 约定未来自动化适配交付要求。

清单明确适配系列 `adapter_id`、修订版本 `version`、宿主接口号、最低主程序版本、渠道、游戏完整版本、精确哈希、x86 架构、固定入口、更新说明与验证级别。`source_root` 相对清单目录解析；其中必须有契约列出的 14 个模块和 `native/`。原生清单由 `native_manifests` 显式列出，工具收集其引用的 DLL。验证记录由 `evidence` 显式列出，只能是清单目录内的 JSON、TXT、MD，每份最多 2 MiB。

每个客户端构建使用独立的适配清单目录；每次源码、DLL、说明或验证记录变化都增加修订号，例如 `11.21-r1 → 11.21-r2`。同一 `adapter_id/version` 已存在不同内容时，制作工具拒绝导入。游戏构建变化需要实际分析和验证，不能仅修改版本号或目标哈希。v1 宿主仍支持 x86 游戏；扩大宿主接口或架构支持时同步发布主程序更新。

`.bcpro` 是可解压的内部 ZIP，布局固定：

```text
manifest.json                 格式、发布元数据、文件哈希、母包标识
payload/*.py                  14 个完整适配模块
payload/native/*.json         原生组件清单
payload/native/*.dll          清单引用的 x86 原生组件
evidence/*                    验证记录
```

每个文件按 SHA-256 登记；`master_id` 是移除自身字段后，对规范 JSON 计算的 SHA-256。规范 JSON 使用排序键、UTF-8、无多余空格；压缩条目排序并固定时间戳。同一套内容与元数据重复制作得到相同母包。母包不带用户身份、设备密钥或发布者私钥。

制作、导入和每次发包前都会重新核对内容清单、路径、语法、已声明入口方法、相对导入边界、原生 DLL 哈希与 PE 架构；这些是静态检查，不会执行适配代码，也不能证明 Hook 行为正确。验证等级和说明来自维护者记录，须如实区分离线验证与游戏实测。母包标识用于内容一致性，不是来源认证；只导入自己制作或可信来源交付的母包。

### 发包边界与故障处理

发包前先检查所有收件配置、最低主程序版本和签名身份；再逐台生成使用独立随机密钥的 AES-256-GCM 密文，设备 RSA-OAEP 封装密钥，发布者 RSA-PSS 签名。签名清单新增 `source_master` 用于追溯，不改动旧客户端解密协议，已用现有 0.9.6 beta 便携包验证实际导入与加载。不要将 `.bcpro` 当成加密包分发，它含有完整明文实现。

一批全部生成并验签后才成为正式输出目录。中途失败时，未完成内容保留在 `.building-*` 中并标记 `FAILED.json`，不要分发；修复磁盘或配置问题后重新生成新批次。每次发包都生成新文件，不覆盖旧批次。设备绑定沿用客户端保护能力，阻止直接转发后使用；不能保证授权设备上的运行时内容绝对不可提取。

### 0.9.6-beta.1：登记与已部署内容持久化修复

旧版把设备登记与已导入包保存在每个安装目录各自的 `output/deployment`。从便携版导出并部署后，改用源码启动入口或另一个解压目录，会被当成另一份未登记安装，出现要求再次导出或 Pro 功能消失的现象；原密钥实际上仍在 Windows 安全存储中。

修复版桌面与源码入口共用 `%LOCALAPPDATA%/BlitzCamera/deployment` 保存本 Windows 用户的登记索引和已部署加密包。项目、设置、更新任务及运行时缓存仍在各安装目录的 `output` 中。首次运行会迁移当前目录内已验证的旧包；共享记录存在时，旧安装目录里的过期包不会覆盖它。输入旧配置制作的包时，会自动匹配原密钥，无需先点击“导出配置”。这不会创建替代私钥来绕过设备校验；缺少原密钥时仍拒绝解密。

补丁 `dist/archive/updates-0.9.6/BlitzCamera-0.9.6-beta-to-beta.1.bcupdate` 用于 `BlitzCamera-0.9.6-beta-release` 基线，约 84 KiB；早期 `BlitzCamera-0.9.6-beta` 构建使用带 `-early-build` 后缀的补丁。两者都部署到 0.9.6-beta.1，保留原配置与包。完整修复版为 `dist/archive/0.9.6-beta.1/BlitzCamera-0.9.6-beta.1.zip`。仍在使用旧版的其他程序副本需要同步安装该修复，才能读到共享记录。
