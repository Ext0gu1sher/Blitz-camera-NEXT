# 工作区裁切不再重排速度曲线（2026-10-22）

旧速度点保存为归一化拍摄进度 `progress`。预览与游戏内时钟都用当前工作区长度解释它，因此将出点提前会把所有速度点一并向前压缩。

`replay_speed` 新增可选 `time_range`，包含 `start_sec`、`end_sec`，保留曲线原有的对局时间范围。旧项目读取时由现有工作区初始化；保存、载入、草稿和撤销重做均携带此范围。修改入点或出点不改变此字段及速度点数据。

曲线仍按原归一化拍摄时间求值，线性和 smooth 过渡保持原数学定义。工作区只选取对应的拍摄时间段。预览时长和离线播放采用 `atWindowCamera` / `atWindowShooting`；时间轴上的速率点位置独立于工作区。恢复出点可再次播放被裁出的原曲线，区间外的点没有被删除。

工作区延伸到曲线之前或之后时，分别保持首、尾倍率。添加区间外的新速度点时才扩展曲线时间范围，按拍摄秒数重新表示原 `progress`，已有点的对局时刻保持不变。

后台从原曲线计算完整 `schedule_seconds`、起始 `schedule_offset` 和本次 `shooting_seconds`。原生时钟支持裁切到曲线中途结束，允许负起始偏移，并以首尾倍率延伸积分。单次播放时长约束保留，原生数据布局未改。已构建并验证 `position_hook_1121.6f81f29154a8.dll`，清单与 DLL 哈希一致。

草稿重算完成时不再恢复旧播放头，避免异步响应覆盖刚选的 I/O 时刻。

验证包含 283 项 Python 测试、原生独立进程的线性与平滑曲线裁切和延伸模拟，以及两个隔离浏览器流程：`tools.test_speed_window_ui` 和 `tools.test_overlay_ui`。界面检查覆盖出点 30 → 18、区间外速度点保留、播放速度与行程、I/O 快捷键、撤销重做、保存重开、首尾倍率延伸及区间外加点。延迟草稿响应另有独立界面断言。

截图保存于 `output/speed-window-acceptance/trimmed-speed-curve.png`。验证使用隔离项目和本地无头浏览器，没有修改用户项目、启动或操作游戏。更新后需重启工作台和本地服务，以使用新的曲线解析和原生模块。
