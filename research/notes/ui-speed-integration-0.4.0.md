## 自测中发现并修复的问题

1. 原生 FOV 平滑可停在与目标相差一个 float ULP 的状态；当前值与投影仍一致，动画/任务已空闲。将目标剩余差的判据设为 1e-5，保留动画空闲、连续稳定采样和投影一致性检查；明显变化仍拒绝。
2. 初始 Python 路径点布局误带了新增日志字段，导致 C 入口以 109 拒绝接管。补齐路径点大小、速度表偏移、共享数据总长等 C/Python 校验，且生产配置写入限定在当前工具的共享块内。
3. 上述布局错误曾将 32 字节速度表写到已停用的旧实验 DLL `replay_time_trial_1121.2fd8c56274dc.dll` 的代码区。只读模块核对确认所有差异都限于这次写入，旧模块 `active=0, detached=7, restored=1`，全部原入口已恢复。按同一构建和加载基址重定位还原了这 32 字节，并验证该模块整个可执行区与磁盘构建一致；当前生产 DLL 的代码也逐字节核验通过。没有改写游戏自身代码。详见 `20261019T142934640438Z/layout-failure-range-audit.json` 与 `owned-module-repair.jsonl`。
4. 传输层新增驻留工具可执行区核对（处理 ASLR 重定位），发现不一致时拒绝复用。补了边界与代码完整性测试。旧端口 56591 曾继续返回旧服务，最终改用并实际验证 56592；页面显示 0.4.0。
