## 1. 当前结论与授权边界

已验证：本地回放暂停时，活动场景的渲染系统所引用的 `FreeCamera` 能响应游戏内置输入，沿当前完整三维视线平移。位置变化与视图矩阵自洽，方向、FOV、投影及回放时钟保持稳定；另一个 `GameCamera` 没有随之移动。

尚未验证：外部程序任意设置 XYZ、独立控制横滚、恢复保存机位、消除后续更新覆盖、每个呈现帧的一致性，以及播放中的精确时间同步。读取与内置输入实验成功，不等于获得了外部摄像机控制权。

此前明确授权的是只读分析、读取进程状态，以及按当时约定由用户或界面工具执行普通游戏输入。本轮最终的 W 平移实验由用户手动完成，分析侧仅后台读取。用户要求推进项目首版，可以推进工作区内的研究记录和实现准备；**不能据此覆盖此前“不写游戏内存、不注入”的限制**。

本文的恢复步骤是待执行方案。运行它之前，需要用户明确把范围扩展为：只在已确认的本地回放中，进行一次预先定义的机位恢复状态修改。若具体实现还涉及远程调用、代码执行或注入，必须单独说明其机制并取得对应授权，不能把它们隐藏在“设置机位”之下。本文不执行这些操作。

## 6. 一次恢复实验：先限定为位置恢复

### 6.1 目标与范围

最小目标：在已确认暂停的同一回放中保存机位 A，由用户只平移到 B，再发出一次恢复操作，使活动 `FreeCamera` 回到 A，检查矩阵是否同步及状态是否被后续更新覆盖。

本次只验证恢复位置，保持朝向和 FOV 不变。它有意不同时试验尚未证实的 roll 或 FOV 设置，避免多个未知量混合。若保持朝向需要同步更新观察目标等伴随状态，必须先从当前实现确认这些依赖，将其列入一次提交事务；不能猜测字段。通过后也只能声称“固定姿态与 FOV 的位置恢复通过”，不能声称完整六自由度机位恢复已通过。

本次恢复是一个逻辑操作，不是持续写入循环。为保证对象内部一致性，实际可能需设置多个经确认的伴随状态；它们的准确清单、顺序和执行时机必须在执行前明确。

### 6.2 执行前必须补齐的实现证据

静态分析已经给出 `FreeCamera` 的 setter、状态更新及矩阵重建线索，详见同目录 `freecamera-update.md`；这些地址不是可直接调用的稳定接口。安全提交线程/阶段、原子操作方式和独立活动场景根仍未闭合。需要得到以下明确答案后才能启动恢复实验：

1. 哪些状态是位置的权威来源，哪些是输入目标、平滑缓存或派生数据？
2. 设置位置是否还需要同步目标点或其他姿态相关状态，才能保持方向不变？
3. 怎样使 view、视锥及相关派生状态正常刷新？不能以裸写矩阵代替这些关系。
4. 该状态在哪条线程、哪个更新阶段安全提交？暂停时该路径是否执行？
5. 如何保证一次操作不会形成只改了一半的相机状态？
6. 选定方式是数据写入、已有调用路径，还是需要运行时代码执行？各自需要的授权必须明示。

若这些答案仍不完整，继续只读定位。不能用试写未证实字段、连续抢写或直接回放整块对象内存作为退路。

### 6.3 前置条件

- 用户已明确授权这一次恢复状态修改；注入或远程调用若需要，已有对应说明和授权。
- EXE 路径、架构和 SHA-256 与本方案匹配；模块定位重新计算，不依赖旧堆地址。
- 联合确认回放上下文、活动场景、渲染系统和 `FreeCamera`；仅断网或仅存在回放对象不足以放行。
- 暂停标志成立，相对时间在连续静置采样中稳定；不处于加载、重启、跳转或相机模式切换期间。
- 用户输入已释放，位置、方向和矩阵已停稳；实验期间不再输入，不切换场景。
- 本次操作内容已经具体到可检查的状态清单和提交方式。实现只准备这一次事务，不开启循环写入或自动重试。

任一前置条件不成立都在写入前终止，不进入在线战斗寻找替代环境。

### 6.4 操作顺序

1. **记录 A。** 在暂停且停稳的机位连续读取至少 2 秒。保留位置、完整方向基底、FOV、view / projection、回放时间，以及 PID / 进程创建身份、构建指纹、对象链。矩阵用于验证，不能未经分析直接作为恢复载荷。
2. **用户平移到 B。** 由用户进行短暂 W 或其他已验证的平移，不转动鼠标、不滚轮。释放输入后等待位置与矩阵停稳。确认 B 与 A 的位置差明显大于浮点及静置噪声，而朝向、FOV 与回放时间仍与 A 一致。
3. **最后检查。** 重新核对进程、对象链、暂停状态和 A / B 的方向、FOV。确保恢复目标仍属于当前场景。任一身份变化、非有限数值或模式不明时终止。
4. **仅恢复一次。** 使用已经完成分析、明确列出的状态设置方式，提交 A 的位置及必要伴随状态；不发送后续纠正写入，不自动重复。
5. **立即观察。** 持续读取位置、方向、FOV、view、投影、绑定数据与回放时间，保留所有完整及被丢弃的样本理由。不得仅回读刚写过的字段就判成功。
6. **观察保持。** 从首次到达 A 起继续采样至少 3 秒，目标为至少 150 个有效样本，确认不会回弹至 B。若已有经过验证的渲染帧计数源，再额外要求覆盖至少 60 个不同渲染帧；没有该来源时只报告采样窗口，不把样本数换算成渲染帧数。
7. **结束。** 撤销实验侧进一步写入能力，继续一次只读身份核验并报告结果。不自动进行第二次恢复。如果异常，需要用户通过正常游戏操作离开自由镜头或重新打开回放；未经约定的自动回滚本身也是另一次修改。

### 6.5 预先固定的验收标准

以下是实验阈值，不是已达到的性能承诺。实施前可基于新的静置噪声分析作有记录的调整，但不能在看到失败后临时放宽。

| 检查 | 通过标准 |
| --- | --- |
| 权限与模式 | 本次全部状态修改仅发生于确认的暂停回放；全程身份及场景链有效 |
| 恢复位置 | 首个后继的完整一致状态达到 A，欧氏位置误差不超过 `0.01` 个游戏世界单位；若观察到明显的逐渐趋近过程，应标为平滑响应而非直接恢复通过 |
| 姿态保持 | 相对 A 的完整朝向差不超过 `0.05°`；若只能验证 direction 而无法验证 up / roll，则不得宣称完整姿态保持已通过 |
| FOV 保持 | 与 A 的有效 FOV 差不超过 `0.01°`，前提是该数值的角度含义已经确认；同时核对投影与宽高比 |
| 矩阵一致性 | 位置与 view 的眼点关系、view / projection 与 VP 的关系均自洽；可先用 `1e-4` 作为当前数值范围下的残差报警阈值，超出时检查矩阵约定和采样完整性 |
| 保持与覆盖 | 到达 A 后至少 3 秒、至少 150 个有效读取样本持续满足上述条件，无需重复写入或持续输入；只能就已观察窗口作结论 |
| 时间 | 相对回放时间不因恢复而推进或跳变，暂停状态持续成立 |
| 画面 | 若当时取得用户观察或经授权的屏幕证据，固定地标应恢复构图；只有读内存证据时，将画面确认单列为未验证 |

“首个后继完整状态”是观测定义，不是“下一渲染帧”的保证。异步采样不能排除两个样本之间的短暂覆盖，也不能可靠测量亚采样周期的响应延迟。

### 6.6 失败分类与后续只读检查

| 现象 | 结论与下一步 |
| --- | --- |
| 刚设置的字段变成 A，随后回到 B | 发生后续覆盖；检查输入目标、平滑缓存或其他更新者。不要加快重复写入来掩盖问题 |
| 位置变为 A，但 view 或绑定保持 B | 派生状态没有刷新、采样跨阶段，或对象不是实际提交来源；检查刷新流程与活动渲染链 |
| 位置恢复同时发生转向 | 位置与观察目标 / 朝向存在耦合；检查设置语义和伴随状态，不能直接归为数值误差 |
| 位置缓慢趋近 A | 可能设置了目标而非直接状态，或仍受平滑影响；记录轨迹，不将其当作即时恢复成功 |
| 原始相机状态正确，但少数绑定采样不匹配 | 先排查通道及读取时序，不能仅凭异步样本断言画面抖动，也不能忽略不一致 |
| 进程、场景或相机身份变化 | 立即停止进一步修改，重新只读识别；不沿用旧快照或指针 |
| 读取失败、非有限值、模式不明或游戏退出 | 不重试写入，保存诊断结果；退出本次实验 |

## 7. 一致性与结论用语

进程读取不具备跨字段、跨对象和跨线程的原子性。应优先读取完整的小块状态，前后复核对象及模式标识，并用连续稳定窗口确认起点、终点和保持状态。中途不一致的样本需要保留计数和原因，不能无记录丢弃后声称全部匹配。

本轮可以写：“暂停时，活动场景渲染系统引用的自由相机发生了与输入方向一致的三维平移，矩阵与位置自洽，采样时钟保持冻结。”

本轮不能写：“已获得完整摄影接口”“任意 XYZ / roll 可写”“每一帧最终画面都已验证”“已经能精确恢复机位”或“已完成 A 步骤”。

只有上述一次恢复实验实际通过，才能推进到后续两机位、8 秒运镜实验。一次固定姿态的位置恢复也不是完整姿态、FOV 恢复的替代证明。
