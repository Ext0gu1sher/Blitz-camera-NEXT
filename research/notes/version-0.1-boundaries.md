# Blitz Camera Lab 0.1：实现边界与下一步门槛

日期：2026-10-14。本文依据当前工作区源码、2026-10-13 至 2026-10-14 的只读运行记录及本构建静态分析整理。编写本文未运行游戏、读取游戏进程或操作 UI；没有新增恢复、写入或注入实验。

## 1. 首版交付的具体范围

0.1 是有实机读取能力的研究原型：严格限定已适配构建，识别回放自由相机，读取/保存机位，在离线项目中编辑并计算轨迹。它还没有让外部程序稳定控制游戏当前画面的能力。

| 能力 | 当前实现 | 验证边界 |
|---|---|---|
| 世界位置 XYZ | 读取相机位置并用 view 眼点关系复核 | 暂停和原生平移已有实测；不代表可写 |
| 姿态 | 从 view 的完整旋转基底生成四元数，并显示工具约定的偏航/俯仰/横滚 | 静态姿态、转向关联已有证据；独立任意 roll 设置没有实测 |
| 水平 FOV | 从透视投影推导，保留原始接口/投影 FOV 和比例 | FOV 操作与投影关联已有实测；那次操作伴随姿态变化，不是隔离的纯 FOV 控制实验 |
| 回放时间 | 读取当前构建原生时钟状态；拒绝未初始化、跳转、重建、时间倒退和明显前跳 | 新门禁下暂停 `35.1522808075` 再次读取通过；播放/变速/跳转时序未实测 |
| 保存机位 | 暂停时捕获相机与原生控制器，保存 JSON，再添加到离线关键帧项目 | 不会把保存结果恢复到游戏 |
| 关键帧编辑 | 时间、XYZ、姿态、水平 FOV 编辑；JSON 导入/导出 | 编辑的是工作区项目 |
| 轨迹求值 | 几何路径、弧长时间分配、缓动、四元数插值、FOV 插值 | 纯数值计算，不修改客户端 |
| 预演 | 浏览器路径/视锥示意、拖动时间、循环预演 | 无游戏地图、碰撞、画面渲染或游戏镜头执行 |
| 重复运镜 | 同一离线项目在同一时间可重复求值 | 尚不能宣称同一回放得到重复游戏构图 |
| 时间轴抽象 | 独立拍摄时间 / 回放源时间的基础映射，回退或会话变化需重新建立锚点 | 未接入游戏相机执行，不能称为已实现回放同步 |
| 恢复、写入、Hook、注入 | 未实现 | 仍受用户此前的明确限制 |

## 2. 构建和代码边界

仅支持本次检查的 Windows Steam 国际版 `11.20.0.887`，SHA-256：

```text
4813544d3d6b9f45a357e87f5a14d065bd108c4acd324ac1506cb6d1ad6ff0af
```

本机安装路径为 `C:\Program Files (x86)\Steam\steamapps\common\World of Tanks Blitz\wotblitz.exe`。读取器从当前进程查询实际路径，以哈希、x86 PE 和运行模块大小核验构建；版本名不是独立兼容条件。

代码职责：

| 文件 | 作用 |
|---|---|
| `blitzcam/memory.py` | Windows 进程/模块枚举、哈希和架构校验、仅查询/读取访问 |
| `blitzcam/profile.py` | 单构建白名单与已分析的类型定位 |
| `blitzcam/reader.py` | 对象关联检查、原生相机/控制器读取、时钟与快照一致性校验 |
| `blitzcam/pose.py` | 视图矩阵、四元数、工具角度约定和水平 FOV 换算 |
| `blitzcam/trajectory.py` | 确定性的离线轨迹求值 |
| `blitzcam/clocks.py` | 离线时间轴映射基础 |
| `blitzcam/project.py` | 项目验证、JSON 存取与离线样本导出 |
| `blitzcam/server.py`、`blitzcam/web` | 本机工作台、显式只读连接、编辑和预演 |

游戏访问申请 `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`。当前模块不提供写内存、远程线程或注入 API；没有自动输入游戏的执行器。只读发现与文件哈希检查不调用被分析的游戏函数。

项目保存、快照保存和导出会写工作区文件，这与“不修改游戏文件”是不同的范围。首版 Python 使用标准库；运行环境为 64 位 Python 3.11。

首版已整合的时钟门禁要求 ReplayPlayer `+0x11/+0x35 == 1`、`+0xA0 != 0`、`+0x2D/+0x2E == 0`、`+0x108 == 0xFFFFFFFF`；原生 Spectator 控制器限定 `+0x10C == 0xFFFFFFFF`、`+0x128 == 0` 的已适配模式。主代理在本轮整合后真实执行只读 `inspect`，当前暂停时间 `35.1522808075` 通过这些检查；本文作者没有另行运行游戏读取。

捕获前后及跨次读取比较 origin、时间倒退与明显前跳。前跳阈值使用 `max(rate_before, rate_after) × elapsed + 0.25 秒`，它是宽松的大跳检测，不是客户端协议，也不能保证发现两次采样间的所有小跳转。捕获恰逢暂停或倍速改变时，样本暂时丢弃。状态门禁代码存在和静态推导吻合，仍需后续用户操作下的动态转换验证。

## 3. 已证实、合理推断、未验证

### 已有直接证据

- 当前构建的 `GameSceneController` 关联回放上下文、`GameCamera`、`FreeCamera` 和 `ReplayCameraController`；`SpectatorCameraController` 另直接引用活动实验中的 `FreeCamera`。
- 实测 `GameScene +0x128/+0x12C`、`RenderSystem +0xB0/+0xB4` 指向响应输入的同一自由相机。原生 W 平移使其位置沿三维视线改变，另一个 `GameCamera` 不动。
- 暂停时原生自由镜头仍能平移；此次采样的回放时间固定为 `35.1522808075`。存在机位与 view / VP 一致性证据。
- 静态代码存在控制器目标位置、角度目标/平滑缓存、FOV 输入/动画相关状态，以及相机 setter 和矩阵 dirty 重建链。
- 当前 ReplayPlayer getter 采用 `(initialized ? raw : 0) - origin`；正常推进按 dt × rate；快进/回退有独立推进门、等待状态和延后重建阶段。
- 本地离线实现将轨迹形状与时间分配分开；匀速选项通过弧长求值而非均匀曲线参数。

### 有证据支持的推断

- 找到的自由相机是当前拍摄控制最有价值的入口，因为场景、渲染系统、原生控制器、输入响应和矩阵相互吻合。
- 要维持外部机位，需要同时处理原生控制器目标/平滑/动画状态及相机派生矩阵，或在明确定义的相机更新阶段接管；只写位置或 view 不足以构成稳定协议。
- 与按键宏相比，未来在确定时间直接求值并提交相机状态，更适合重复运镜；但这条执行路径尚未实现或实测。

### 仍未验证

- **engine-active-root**：尚未从独立引擎活动根节点完整定位到当前场景。当前扫描和正向关系能加强只读判断，但无法仅靠唯一候选彻底排除遗留的完整对象图。
- 每个最终呈现帧使用哪次状态、渲染绑定所有通道的一致性，以及跨相机/控制器/渲染线程的原子快照。已有停稳检查中绑定 `149/151` 次匹配，不能改写为全部帧通过。
- 一次外部位置恢复、完整姿态/FOV 恢复、更新后是否覆盖、实际画面是否恢复、任意滚转、碰撞/平滑是否可被稳定接管。
- 播放、暂停切换、倍速、前跳、后跳、重新开始、结束时的完整时序，以及每个新门禁字段的动态行为。
- 独立拍摄时间驱动游戏镜头、与回放时间同步、相同回放重开后的游戏构图重复性。

快照明确标记 `frame_synchronized: false`、`active_root_verified: false`、`engine_tick_fence: false`，并记录读窗口和前后时钟。连续两次读数相等、矩阵自洽和前后身份检查提高可信度，但不等于冻结游戏，也无法保证没有短暂变化发生在两个采样之间。

## 4. 8 秒示例证明什么

`examples/eight-second.json` 使用此前 W 平移的起终点，给它们赋予新的 0 秒、8 秒时间戳。用户实际报告按 W 约 2 秒；采样没有可靠的按键起止时间戳，观测到的位置变化区间也不能直接视为按键持续时间。

因此，这个项目只用于验证离线轨迹：总时长 8 秒、端点准确、姿态/FOV 插值、约束条件下的空间匀速、JSON 往返及随机时刻重复求值。100 Hz 导出 801 个数值样本不代表生成了游戏视频帧，也不代表 B 步骤已完成。

选择全路径弧长分配时，中间关键帧时间会被重新分配；搭配缓动后速度会按设计变化。平滑路径可能过冲或穿障碍；当前没有地图和碰撞模型。混合移动路径中的原地转向/FOV 段不能在全路径匀速模式中无时长地消失，应使用遵守关键帧时间模式。

本轮主代理另完成工作台实测：连接只读客户端、暂停捕获写入 QA 项目、编辑 XYZ / 角度 / FOV、保存 3 个关键帧并生成 8 秒、60 Hz 的 481 个预演数值样本。相关产物为 `output/qa-project.json`、`output/captures` 和 `output/qa/workstation-live.jpg`。这些验证覆盖工作台交互和本地数据流，仍然没有执行游戏轨迹。

## 5. A 步骤的下一次实验门槛

**A 的读取部分已有实测，恢复部分没有通过。** 下一次最小实验先限定为：固定姿态和 FOV，用户从已保存 A 平移到 B，实验侧仅做一次成套位置恢复，再观察是否维持。完整 XYZ + 姿态 + FOV 恢复应在这个子实验之后单独验证。

执行前须完成：

1. 取得针对这一次状态修改的明确授权。若选用原生调用、远程执行、Hook 或注入，必须把机制具体说明；“继续研究/产出首版”不自动覆盖此前禁止事项。
2. 补齐引擎活动根到当前本地回放场景的可靠验证，或获得同等强度、经实际切换场景测试的活动判据；不能仅用对象类型存在作为未来写入门禁。
3. 明确一次恢复的最小权威状态：相机位置、保持视线所需的目标/方向关系、原生控制器目标位置，以及输入残留和平滑的处理。不得复制整个对象、vtable、引用计数、指针或动画对象。
4. 确认缓存刷新语义及提交线程/阶段。已找到 setter 和 dirty 链，但尚未取得可安全提交的执行机制；不能把外部零散写入视为原子事务。
5. 严格核验构建、对象链、暂停和稳定状态。现有门禁已组合检查活动、初始化、快进/等待及排队状态；刚清除跳转标志时仍应等待恢复完成。新门禁在当前稳定暂停下已读通，但跳转/重建期间的动态验证仍须补齐。
6. A 与 B 之间只有已验证的平移；方向、FOV、回放时刻不变。出现模式改变、对象重建、未释放输入、无效值或读失败即终止，不自动试写重试。

具体一次实验：暂停停稳记录 A 至少 2 秒 → 用户平移并停稳得到 B → 最后核验 → 提交一次经审查的状态事务 → 连续只读观察至少 3 秒、至少 150 个有效样本。通过条件预先固定：位置误差 ≤ `0.01` 世界单位，完整姿态差 ≤ `0.05°`，有效 FOV 差 ≤ `0.01°`，矩阵自洽、回放时间不变，并且无需反复写入就能维持。阈值是实验标准，不是已达性能。

若有可用且已验证的渲染帧计数，应另覆盖不同渲染帧；没有时只能报告观察窗口与样本数。需要用户或经授权画面证据确认地标构图；只回读改过的字段不能证明画面恢复。

失败时按证据分类：回弹查原生控制器覆盖；位置正确但 view 错查刷新和采样阶段；发生转向查 target/position 耦合；缓慢趋近查目标与直接状态区别；绑定不匹配查渲染通道与非原子读。不能用持续抢写掩盖失败。

固定姿态位置恢复通过后，再验证完整机位恢复，随后才进行 B 的两机位 8 秒游戏运镜、C 的重开重复性和 D 的两种时间驱动。首版离线 `TimelineClock` 不替代这些实验。

推荐路线是定位**原生 Spectator 更新链中的受控提交点**，协调目标位置、平滑状态、姿态和派生矩阵，再从一次位置恢复推进到 8 秒控制。它比只写 FreeCamera XYZ 更接近真正掌握更新来源。现有静态分析给出了具体路径，但提交机制、线程时机、覆盖规则和授权都还没有补齐；本文没有给出可直接调用的稳定游戏 API。

不优先依赖键鼠宏，因为输入持续时间与原生平滑会影响终点；不优先连续抢写相机字段，因为无法可靠保证同一帧所有状态一致；配置或解除碰撞的资源改动也尚未证明能提供精确姿态控制接口。

| 后续步骤 | 依赖与观察方法 | 通过方向与失败排查 |
|---|---|---|
| B：两个机位，8 秒 | A 恢复及受控提交通过；先固定姿态/FOV、独立拍摄时钟，记录求值目标、实际相机、控制器、矩阵和可用帧标识 | 在预先规定的时间/位置误差内到达并保持终点，不靠重复纠偏隐藏覆盖；偏离目标查更新者，突变查时序和原子提交，匀速误差查弧长求值与实际跟随 |
| C：重开同一回放重复 | B 通过；确认回放身份、重新发现对象、取得同一回放时刻的锚点，多次比较实际机位和固定地标 | 构图和姿态达到预先固定误差；差异查锚点、地图/回放身份、初始化与原生平滑残留，不能复用旧 heap 地址 |
| D1：战斗暂停、镜头运动 | A/B 通过；回放时钟持续冻结，独立拍摄时钟驱动 8 秒运动 | 镜头完成路径而回放时间保持不变；若镜头也停止，查提交点是否依赖暂停后的战斗 tick |
| D2：镜头与战斗同步 | 先补完正常播放/变速/暂停/跳转时钟验证，再让轨迹直接依回放时间求值 | 暂停停镜、恢复续行、倍速只改变墙钟耗时；跳转或重建使当前同步段失效后重新建立锚点。漂移查累计墙钟误差、跨帧时序和漏检的状态变化 |

当前没有实机 B / C / D 结果。上述均是后续验收依赖，离线 8 秒示例和预演通过不能填补它们。

## 6. 兼容性、维护与规则

这是每构建适配的私有客户端研究，不是已确认的官方摄影 API。更新后必须重验对象布局、相机更新者、setter/缓存语义、渲染关联和回放状态；即使表面字段仍能读到合理值，也不能直接复用旧结论。后续若引入运行时提交机制，线程与调用约定还会增加维护成本。

没有证据表明运营方已许可本工具。本地回放拍摄或只读实现不自动获得许可；规则风险与未来运行时修改方式需按适用官方规则重新核对。本文不承诺账号风险为零。
