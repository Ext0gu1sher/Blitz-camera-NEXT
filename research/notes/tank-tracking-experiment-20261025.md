# 坦克高精度跟踪：独立实机实验

2026-10-25。已实现并运行，尚未接入工作台正式界面。

## 结论

在已适配的 Steam 11.21 客户端，本地回放可以直接跟随指定坦克的 `TankVisual` 显示变换。决定精度的主要因素是求值阶段：原有相机更新发生在本帧坦克显示变换更新之前，直接在那里读取会落后一帧；实验将相机求值移到 `GameScene::Update` 返回后，消除了本次样本中观察到的滞后。

支持选择坦克实体、车后跟随、侧拍、环绕、车体局部锚点、距离/高度/FOV，以及可选相机位置阻尼。阻尼只作用于相机位置，随后重新瞄准当前目标，不对瞄准点额外平滑或预测。默认不启用阻尼。

## 实测结果

同一份 FVE Defender 回放，两个不同实体。指标为：在阴影绘制入口，读取该时刻 TankVisual 锚点及相机 view/projection，投影到 1920×1080，计算锚点相对画面中心的偏移。只统计正式播放阶段，排除镜头进场过程。

| 样本 | 有效绘制帧 | 中位数 | 95 分位 | 最大偏移 |
| --- | ---: | ---: | ---: | ---: |
| 原相机更新阶段，车后跟随，0.5× | 206 | 3.043 px | 4.554 px | 4.998 px |
| 场景更新后，车后跟随，0.5× | 218 | 0.000194 px | 0.000450 px | 0.000591 px |
| 场景更新后，侧向偏移 5m / FOV 35° / 位置阻尼 0.15s，1× | 142 | 0.000803 px | 0.002104 px | 0.003230 px |
| 场景更新后，另一辆坦克 / 半径 10m / 30°每秒环绕，1× | 147 | 0.000481 px | 0.001790 px | 0.002051 px |

后三组共 **507 帧**，相机求值阶段到绘制入口之间的目标锚点位移均为 0；无缺失配对、无无效目标、无投影到相机后方的样本。首组该位移的中位数为 0.116m，其“上一绘制帧的目标”反而接近画面正中心，支持“一帧滞后”的判断。

这些是不同连续片段，表格不是同一段回放逐帧 A/B 重演。后一组中将“上一绘制帧目标”投影到当前相机的结果是时序误差对照，不是另一台真实相机拍摄的结果。

**上述小数是变换与矩阵层面的测量，不是最终录屏画面达到 0.0033 像素的保证。** 尚未验证最终呈现帧、屏幕抖动、动态遮挡、视锥裁剪、模型隐藏、后处理或炮塔/炮管骨骼。目标锚点是 TankVisual 根变换下的局部点，默认 `[0,0,1.5]`；不是自动识别的炮塔中心或炮口。

四次完整播放均完成撤钩、恢复原倍率并暂停回放；另做一次提前停止实验，30 个有效绘制样本，确认新增场景回调也已恢复。原回放 SHA-256 均未改变。

## 与 WotbTools 离线重建的对照

使用项目当前固定的 Agent/WotbTools 解析和采样版本，不附加固定 0.2s 补偿。将同一原始回放时间的重建车体根位置与实机 TankVisual 根位置比较：

| 样本 | 未修正位置误差中位数 | 本片段最优采样时间偏移 | 修正后位置误差中位数 / 95 分位 |
| --- | ---: | ---: | ---: |
| 首组跟随 | 1.262m | -150ms | 0.039m / 0.104m |
| 改进后跟随 | 1.549m | -155ms | 0.018m / 0.090m |
| 近距离侧拍 | 1.424m | -170ms | 0.043m / 0.099m |
| 第二目标环绕 | 2.663m | -195ms | 0.071m / 0.753m |

偏移是在每段观测内搜索 -250…250ms、步长 5ms，使根位置 RMS 最小得到的诊断值，**不能作为整场固定校准值**。这里只能说明重建与本客户端显示状态存在时间/运动重建差异；不能把全部残差都归因于网络延迟。第二目标还出现较大的逐帧显示位置变化，稳定构图不代表目标动画本身连续平滑。

离线重建仍适合选目标、设计镜头和预览；精密实机拍摄优先使用实际显示变换。两种途径应共用目标与构图参数，但不能把离线预览误差承诺成实机误差。

## 实现边界

- 仅用于已支持的 11.21 本地回放。进入自由镜头并暂停后启动。
- 按回放来源、场景、实体 ID、TankVisual 类型和 TransformComponent 所有者核对目标。每帧再次验证引用、矩阵和相机边界；不跨回放持久化内存地址。
- 根对象仍存在时，隐藏/遮挡不一定导致引用失效。目前不提供自动判断可拍摄状态、丢失后切镜、重生后重新绑定或碰撞避障。
- 相机在场景更新后重新求值，绘制入口仅记录。场景内部是否已有部分视锥裁剪、最终画面边缘有无闪烁，仍需视觉验收；未为追求指标修改绘制入口中的目标数据。
- 阻尼依赖本次播放的采样历史，启动时重置。默认无阻尼模式直接按当前显示变换求值；阻尼模式尚不是任意拖动后严格一致的离线轨迹。
- 复用现有心跳、相机/回放身份检查、输入中断、暂停恢复、共享数据写入范围和撤钩流程。新增的场景回调恢复另行检查。
- 实验驱动始终驻留到游戏退出，但完成后实例回调已恢复。产品源码、产品 DLL、工作台当前项目和游戏安装文件没有被本实验修改。

## 运行

在仓库根目录：

```powershell
python -B research/scripts/build_tank_tracking.py

# 默认只读检查，列出当前场景实体；默认选择回放录制者。
python -B research/scripts/tank_tracking_trial.py

# 三种镜头，均从当前暂停点开始，结束后暂停并交还镜头。
python -B research/scripts/tank_tracking_trial.py --execute --preset chase --seconds 4
python -B research/scripts/tank_tracking_trial.py --execute --preset side --seconds 4 --distance 8 --height 4 --smooth 0.15
python -B research/scripts/tank_tracking_trial.py --execute --preset orbit --seconds 4 --eid 6883668 --orbit-speed 30
```

示例实体 ID 仅属于本次回放；换回放先运行只读检查。CLI 可设置 `--anchor x y z`、`--fov`、`--rate`。单次片段 0.5–12 回放秒，实际拍摄时长仍受现有播放器 120 秒上限限制。`--phase update` 重现较早求值阶段；默认 `--phase scene`。`--lag-frames 1` 故意使用上一更新帧瞄准点，仅用于对照。`--stop-after 0.7` 验证提前停止。

每次结果写入 `output/tank-tracking-experiment/runs/<UTC时间>/`：

- `report.json`、`events.jsonl`：复用的相机/回放原生日志。
- `tracking-targets.json`：与原生日志按 commit 配对的目标矩阵。
- `tracking-report.json`：设置、来源哈希、测量指标、状态与记录丢失计数。
- `reconstruction-comparison.json`：执行下述只读对照后生成。

```powershell
node research/scripts/compare_tank_tracking.mjs output/tank-tracking-experiment/runs/<UTC时间>
python -B -m unittest tests.test_tank_tracking_experiment tests.test_replay_preview tests.test_replay_clock
```

本轮上述 Python 测试 21 项通过。构建还运行 x86 原生自测：275 组朝向、错误实体身份、错误矩阵、目标延迟对照、位置阻尼不延迟瞄准、相机边界。
